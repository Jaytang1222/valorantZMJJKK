# VALO 一把：需求规格

## 1. 范围与术语

本文件定义 MVP/V1 的可验收需求。`题目快照` 指冻结的选手属性版本；`结算` 指服务端写入最终成绩且不再允许提交猜测；`自动判负` 指断线超过规定时限后，系统将该用户标记为本局失败且拒绝其后续操作。

优先级采用 MoSCoW：M=必须、S=应当、C=可选、W=本版本不做。

## 2. 功能需求

### 2.1 身份与账户

| ID      | 优先级 | 需求                                                                            | 验收标准                                                                                 |
| ------- | ------ | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| AUTH-01 | M      | 用户使用邮箱和密码注册及登录；邮箱按规范化后的值唯一。                          | 首次注册生成唯一用户并安全保存密码哈希；再次登录恢复同一账户，接口不返回密码或密码哈希。 |
| AUTH-02 | M      | 未注册用户可选择游客模式试玩单人对战和查选手。                                  | 游客使用临时显示名，成绩仅保存在设备会话，不能进入排行榜或联机对战，也不能自定义昵称。   |
| AUTH-03 | M      | 注册成功后平台分发 `瓦友#xxxxxx` 格式的随机默认显示名；登录用户不能修改显示名。 | 默认后缀仅使用字母和数字；账户页只读显示平台名称与邮箱，不存在修改昵称 API。             |
| AUTH-04 | S      | 用户可导出或删除自己的账户数据。                                                | 删除后个人资料不可访问，审计记录按隐私策略匿名化。                                       |

### 2.2 单人对战

| ID           | 优先级 | 需求                                                                                               | 验收标准                                                                         |
| ------------ | ------ | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| SOLO-01      | M      | 单人对战提供入门、简单、完整三种难度，并可随时开始随机题目。                                       | 创建尝试时必须指定一种有效难度，且不受日期或每日次数限制。                       |
| SOLO-02      | M      | 三种难度均最多接受 8 次有效猜测。                                                                  | 第 8 次错误后自动结算为失败；结算后接口拒绝新猜测。                              |
| SOLO-03      | M      | 每次猜测返回字段逐项比较结果。                                                                     | 响应仅含匹配状态和必要方向提示，不含目标选手 ID/别名。                           |
| SOLO-04      | M      | 搜索支持标准名和已录入别名，且选择候选后才提交。                                                   | 大小写、首尾空格和常见 Unicode 变体不影响定位。                                  |
| SOLO-05      | M      | 答对、失败或放弃时展示结算结果。                                                                   | 展示目标选手、正确属性、猜测数、服务器用时、分数与分享文本。                     |
| SOLO-06      | M      | 单人对战从对应难度的已审核题池抽取；Alpha 验证阶段允许重复抽题，不设置题池不足告警或创建阻断。     | 创建单人局时仅从已批准且启用的选手快照抽取。                                     |
| SOLO-07      | S      | 入门难度在首次错误后提供一次战队历史摘要提示。                                                     | 提示不显示目标姓名、别名或唯一身份标识，且不额外消耗猜测次数。                   |
| GAME-ATTR-01 | M      | 猜测比较字段包含赛区、国籍、主位置、当前或最近效力队、冠军赛冠军次数、大师赛冠军次数和英雄 Top 3。 | 不得展示主要使用语言、首次顶级赛事年份或国际赛最佳成绩；数值字段返回高/低/相等。 |
| GAME-ATTR-02 | M      | 国籍除精确与不符外支持“相近”状态。                                                                 | 两个国籍归属同一预定义地理分区时返回相近；分区表由后台版本化维护。               |

### 2.3 多人对战

| ID    | 优先级 | 需求                                                                        | 验收标准                                                                                      |
| ----- | ------ | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| VS-01 | M      | 已登录用户可通过在线匹配进入对战，或创建固定双人 BO1 私密房并设置回合时长。 | 匹配仅对相同回合时长的等待用户配对；服务端只接受 2 人、1 回合和 30/60/90 秒。                 |
| VS-02 | M      | 私密房以固定 6 位邀请码加入，不提供公开房或大厅。                           | 邀请码仅含大写字母和数字且长度恒为 6；无效、满员或已开始房间返回明确错误。                    |
| VS-03 | M      | 仅房主可在 `LOBBY` 启动，并且至少两人已准备。                               | 倒计时开始后房间设置锁定。                                                                    |
| VS-04 | M      | 每一回合由服务器同步启动、计时、校验猜测和结算。                            | 不同客户端显示的剩余时间与服务器相差不超过 1 秒。                                             |
| VS-05 | M      | 每名玩家每回合最多有 8 次猜测。                                             | 超额猜测不改变状态与分数，并返回错误码。                                                      |
| VS-06 | M      | 每局胜方获得 1 分。                                                         | 猜对、投降获胜和断线超时获胜均只增加 1 分。                                                   |
| VS-07 | M      | BO1 结束后服务端生成胜者；双方确认再来一局时保留累计比分。                  | 所有人收到一致的结算结果；任一方退出可返回联机主菜单。                                        |
| VS-08 | M      | 断线用户可在 20 秒内重新接入原房；超过 20 秒未重连自动判负。                | 20 秒内通过身份验证可恢复成员状态和当前回合可见信息；逾期后记录本局失败、拒绝重连与后续猜测。 |
| VS-09 | S      | 房主离开时将房主转移给另一名在线成员；无活跃成员时清理房间。                | 显式退出清理恢复标记；已结束房在展示期后自动关闭。                                            |

## 3. 非功能需求

| 类别     | 要求                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------- |
| 性能     | 普通 API P95 < 500ms；猜测事件端到端 P95 < 300ms；支持 1,000 同时在线与 100 个活跃房间作为 V1 容量目标。  |
| 可用性   | 月可用性目标 99.5%；题池不足、匹配队列异常和房间结算失败须告警。                                          |
| 安全     | 全站 TLS；会话使用 HttpOnly/Secure cookie；后台强制管理员角色；输入按 schema 验证；OWASP 常见攻击有防护。 |
| 反作弊   | 答案、计时、计分均以服务端为准；限流和行为日志覆盖猜测、入房与建房。                                      |
| 隐私     | 最小化收集数据；提供隐私政策、账号删除入口与数据保留期限。                                                |
| 可访问性 | 键盘完成搜索/提交；颜色有文本/图标冗余；满足 WCAG 2.1 AA 的关键流程。                                     |
| 国际化   | MVP 界面先支持简体中文与英文；数据层以稳定枚举和本地化显示名分离。                                        |
| 可观测性 | 结构化日志带 requestId；错误追踪、指标和发布/题库告警可查询。                                             |

## 4. 业务规则

- 猜测只能选自当前可猜选手列表。禁用选手在历史猜测中保留显示，但不能作为新猜测。
- 分数计算在服务端完成并保存输入参数；规则变化须以 `scoringVersion` 标记，不重算已结算记录。
- 在线匹配对局仅在正常结束、两名玩家完成且未触发风控时才有资格计入多人榜；私密房默认不入榜。
- 每个难度的可用题池低于 30 道时必须告警；低于 10 道时停止创建对应难度的新单人局。

## 5. 不纳入本期

- 现金、虚拟币、抽奖和可兑换奖品。
- 官方赛事数据实时同步承诺。
- 语音聊天、好友系统、观战、录像回放。
- 原生 iOS/Android 应用与跨平台账号迁移。
