# VALO 一把：开发任务拆解

## 1. 交付原则

按“数据可信 → 单人闭环 → 实时对战 → 排行与运营”的依赖顺序实施。每个任务完成须有代码审查、自动化测试和可观测性检查；任何涉及题目或计分的改动须保留版本号。

## 2. 里程碑

| 里程碑         | 目标                           | 完成定义                                 |
| -------------- | ------------------------------ | ---------------------------------------- |
| M0：基础       | 可部署、可测试的工程与数据模型 | 预览环境可访问，迁移和 CI 全绿           |
| M1：单人 Alpha | 查选手与三难度单人对战完整可玩 | 从登录到结算的端到端用例通过             |
| M2：社交 Beta  | 在线匹配与房间联机对战稳定运行 | 双人 BO1 可重连，超时判负且一致结算      |
| M3：V1 运营    | 总排行、后台与风控             | 可支持受控公开测试并处理内容问题         |

## 5. 风险清单

| 风险                       | 影响 | 缓解与负责人                                             |
| -------------------------- | ---- | -------------------------------------------------------- |
| 转会或资料错误使题目不公平 | 高   | 仅使用快照；双人审核和一键停用，内容编辑负责。           |
| 客户端泄露答案或伪造计分   | 高   | 服务端权威题目/时间/计分；安全评审与渗透测试，后端负责。 |
| 多人同步在弱网下不一致     | 高   | 状态机、序列号、可重连设计和压测，实时工程负责。         |
| 第三方数据许可不清         | 高   | 来源台账、条款复核与更正通道，产品/法务负责。            |
| 题库不足导致重复感         | 中   | 先建 365 题缓存并监控曝光频率，内容编辑负责。            |
| 排行榜被脚本刷分           | 中   | 限流、风险规则、审计及人工处置，后端/运营负责。          |
