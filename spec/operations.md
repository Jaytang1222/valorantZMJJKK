# M3 运行与发布手册

## 当前责任边界

- Railway API、PostgreSQL、Redis 与 Vercel 的部署、环境变量和外部平台配置由产品负责人执行。
- 代码库负责迁移、健康检查、结构化错误上报、发布清单与回滚步骤。
- PostgreSQL 备份目前未启用。正式发布前必须接受数据不可恢复风险，或由产品负责人补充备份与保留策略。

## Sentry

- Web 与 API 项目应分别配置错误告警，接收邮箱为 `jaytang12221@outlook.com`。
- 建议规则：新问题立即通知；同一问题 5 分钟内达到 10 次事件时再次通知。
- 在 staging 以受控测试错误验证两个项目均能收到事件，避免在生产制造测试异常。

## 发布清单

1. `staging` 部署完成，数据库迁移日志成功，`/health` 返回正常。
2. Vercel Preview 与 Railway staging 使用同一提交；完成对应功能的人工回归。
3. 在 GitHub 提交 `staging -> main` PR，确认格式、lint、类型检查、测试与构建全绿。
4. 合并后确认 Railway production 迁移成功、Vercel Production 已更新。
5. 生产仅执行轻量回归，不执行负载压测：注册/登录、单人结算、私密房、在线匹配、排行榜读取。
6. 检查 Sentry Web/API 无新增未处理错误；记录本次版本、迁移与回归结果。

## 迁移回滚

1. 暂停继续发布并记录失败迁移文件与 Railway 部署日志。
2. 不对生产数据库执行未审查的回滚 SQL。优先发布前向修复迁移。
3. 只有在已验证备份可恢复时，才执行数据库恢复或破坏性回滚。
4. 恢复后执行 `/health`、登录、单人结算和联机房回归，并检查 Sentry。
