# 当前产品决策（2026-08）

本节优先于本文中较早的 M2 设想。

- 联机模式固定为双人对战，单局为 BO1；每名玩家每局最多 8 次猜测。
- 联机入口仅保留在线匹配、创建私密房与通过固定 6 位邀请码加入私密房；不提供公开房或房间大厅。
- 对局开始后进入独立对战页。本人可见完整猜测字段和结果，对手仅可见颜色进度。
- 猜对、对手投降或断线超时获胜均记 1 分；双方确认再来一局时保留累计分数。
- 断线用户可在 20 秒内恢复原房；到期自动判负。显式退出清理房间恢复标记，已结束房在短暂展示期后自动回收。
- 注册用户仅使用平台分配的 `瓦友#xxxxxx` 显示名；不提供用户自定义昵称。
- 每个联机回合持久化冻结题目、猜测明细、胜者和结束原因，作为排行榜与战绩页面的可复算数据源。

# VALO 一把：产品与技术设计

## 1. 产品定义

**VALO 一把**（暂定名）是面向 VALORANT 社区的职业选手身份猜测游戏。玩家根据目标选手的赛区、国籍、位置、所属队伍、效力历史、赛事成绩等线索，在有限次数内猜出该选手。产品只提供单人对战、联机对战和查选手三个入口，并以总排行榜承载长期竞争。

它借鉴“弗一把”的低门槛猜选手节奏，但题库、属性和胜负规则均围绕 VALORANT 设计；不使用 Riot 官方背书，也不暗示与 Riot Games 或 VCT 存在合作。

### 目标与非目标

| 目标                                 | 非目标（MVP）                    |
| ------------------------------------ | -------------------------------- |
| 让了解 VCT 的用户在 1 分钟内完成一局 | 竞猜、押注或任何可交易奖励       |
| 以难度、对战和总排行带来回访         | 直播、观战和语音聊天             |
| 以房间对战支持好友娱乐与竞技         | 自动抓取未经授权的第三方受限数据 |
| 题库可审核、可修正、可追溯           | 覆盖全部历史半职业选手           |

### 核心用户

- **休闲 VCT 观众**：按自己选择的难度完成一局，分享结果。
- **硬核赛事粉丝**：追逐速度、胜率和总排名。
- **好友房主**：创建私密房间，组织 2–8 人对局。
- **运营编辑**：维护选手档案、题目和数据版本。

## 2. 游戏设计

### 2.1 题目与猜测

一题对应一名已发布的职业选手快照。玩家从可搜索的选手别名中选择答案；每次错误猜测会返回属性比较结果。

| 属性             | 展示方式           | 判定示例                                   |
| ---------------- | ------------------ | ------------------------------------------ |
| 赛区             | 精确/不符          | Pacific                                    |
| 国籍             | 精确/相近/不符     | Korea；同一地理分区为相近                  |
| 主位置           | 精确/部分匹配/不符 | Duelist；同定位池为部分匹配                |
| 当前或最近效力队 | 精确/不符          | Sentinels                                  |
| 冠军赛冠军次数   | 高/低/相等         | 1，显示方向                                |
| 大师赛冠军次数   | 高/低/相等         | 2，显示方向                                |
| 英雄 Top 3       | 精确/部分匹配/不符 | Jett / Sova / Omen；命中任一英雄为部分匹配 |

“当前”统一指题目数据版本中的日期，避免转会造成历史题目答案变化。玩家可选择难度：

- **入门**：8 次猜测，显示全部字段，并在首次错误后额外展示所属战队历史摘要。
- **简单**：8 次猜测，显示全部字段。
- **完整**：8 次猜测，显示全部字段，不提供额外提示。

答案须是题目快照中存在的标准 `playerId`；别名仅用于检索和展示。服务器规范化大小写、空白和 Unicode，防止输入形式造成误判。

“查选手”是非猜测资料入口：用户可按名称、赛区、国籍、位置和战队检索已审核的公开选手档案，不存在猜测次数、得分或胜负。

### 2.2 单人对战

- 用户从入门、简单、完整三种难度任选其一开始随机题目；同一用户可重复游玩，不设每日次数或日期限制。
- 题目按难度配置抽取，避免短期重复，并排除已禁用或低置信度选手。
- 答对、耗尽 8 次猜测或主动放弃后展示答案、属性、个人用时和分享卡片。

单人积分建议：`max(100, 1200 - 120 × 错误次数 - min(300, 用时秒数 × 2))`。总排行榜累加所有有效单人对局分数；同分以较短累计用时优先。

### 2.3 多人对战

联机对战提供**在线匹配**和**创建房间**两种进入方式。在线匹配将条件相同的等待玩家配对；房主可创建公开或私密房，私密房邀请码固定为 6 位大写字母和数字。房间可选择 1、3 或 5 回合；每回合使用一题。房间状态为 `LOBBY → COUNTDOWN → PLAYING → ROUND_RESULT → FINISHED`。

- 每回合每位玩家最多 8 次猜测，默认 60 秒；题目、计时和判定完全由服务器控制。
- 选手每一回合顺序独立洗牌；不能从客户端题库推导答案。
- 首个答对者获得 1000 分，之后答对按剩余时间线性衰减至 300 分；未答对为 0 分。
- 回合结束展示答案和回合榜 8 秒；总分最高者获胜，依次以答对回合数、总耗时、随机种子打破平局。
- 玩家断线后 20 秒内可凭会话令牌重连；超过 20 秒未重连则自动判负，立即结束其本局参与资格且保留断线前已结算回合分数。

MVP 的多人仅支持 2–8 名已登录玩家，不设观战；匹配模式可在自定义房稳定后新增。

## 3. 信息架构与界面

```text
首页
├─ 单人对战
│  ├─ 入门
│  ├─ 简单
│  └─ 完整
├─ 联机对战
│  ├─ 在线匹配
│  ├─ 创建房间
│  └─ 输入 6 位邀请码
├─ 查选手
├─ 排行榜
│  ├─ 总榜
│  └─ 单人 / 联机
└─ 个人中心
   ├─ 最近 3 局详细战绩
   └─ 单人/联机局数、胜率、平均猜测数
   └─ 账号与显示名
```

游戏页优先保证移动端单列体验：顶部为模式、剩余次数/时间；中部为搜索框和候选列表；下方为可横向滚动的猜测属性表。颜色不是唯一信号：精确、部分、错误、高/低还应配图标与文字，满足色觉可访问性。

## 4. 系统设计

### 4.1 建议架构

```text
Web / Mobile Web (Next.js)
        │ HTTPS + WebSocket
API 服务（认证、题目、成绩、排行榜） ─── PostgreSQL
        │                                      │
实时房间服务（Socket.IO / WebSocket） ───── Redis
        │
管理后台（选手、版本、题目审核）
```

建议使用 TypeScript 全栈：Next.js 提供 Web 与管理端，NestJS/Fastify 提供 API，Socket.IO 提供房间事件，PostgreSQL 保存权威数据，Redis 承担房间临时状态、限流和排行榜缓存。MVP 可先让 API 与实时服务同仓部署，按房间并发拆分。

### 4.2 领域模型

| 实体               | 关键字段                                                                | 说明             |
| ------------------ | ----------------------------------------------------------------------- | ---------------- |
| `User`             | id, displayName, authProvider, createdAt                                | 登录用户         |
| `Player`           | id, canonicalName, aliases, status                                      | 标准选手实体     |
| `PlayerSnapshot`   | id, playerId, dataVersion, region, role, team, debutYear, bestPlacement | 可冻结的题目数据 |
| `Puzzle`           | id, snapshotId, mode, publishAt, seed, status                           | 已审核题目       |
| `SoloAttempt`      | userId, puzzleId, guesses, startedAt, finishedAt, score                 | 单人权威记录     |
| `Room`             | id, code, hostId, settings, state, roundIndex                           | 对战房间         |
| `RoomParticipant`  | roomId, userId, score, connectionState                                  | 房间成员         |
| `Guess`            | attempt/roundId, userId, playerId, createdAt, result                    | 审计与回放       |
| `LeaderboardEntry` | scope, period, userId, score, rank                                      | 可缓存的聚合结果 |

`Puzzle` 永远引用 `PlayerSnapshot` 而非可变的 `Player` 属性。编辑数据会建立新 `dataVersion`，不会重写已发布题或已结算记录。

### 4.3 服务边界与接口

- `POST /auth/*`：OAuth 或邮箱验证码登录；游客使用受限匿名会话。
- `GET /players`、`GET /players/:id`：查选手入口，提供公开选手资料与筛选搜索。
- `POST /attempts`、`POST /attempts/:id/guesses`：单人流程；创建时指定 `beginner|easy|full`。猜测响应只返回比较结果，绝不返回答案 ID。
- `POST /matchmaking/queue`、`DELETE /matchmaking/queue`：在线匹配队列；`POST /rooms`、`POST /rooms/join`、`GET /rooms/:code`：房间生命周期。
- WebSocket 事件：`room:state`、`round:start`、`guess:submit`、`guess:result`、`round:end`、`game:end`。所有事件含 schema 版本和 room/round 序号。
- `GET /leaderboards?mode=solo|versus`：总榜游标分页，返回当前用户相邻排名。
- 管理 API：选手/快照 CRUD、CSV 导入、题目预览、难度题池审核与撤回。

## 5. 数据、内容与合规

选手资料应来自公开可用且许可清晰的来源，并记录 `sourceUrl`、采集时间、编辑人和证据备注。Riot API 能满足的部分优先遵循其开发者政策；赛事维基或社区数据须人工复核。使用选手姓名、队名、赛事成绩时应提供资料更正入口和版权/商标声明。

初始题库目标为 250 名有稳定公开履历的 VCT/Challengers 选手，并为每种难度准备至少 100 道审核过的随机题。每名选手需有至少两个可区分字段；低置信度资料不可发布。

## 6. 公平性、安全与可观测性

- 服务器生成单人题和多人回合种子，并在结算后才公开答案；客户端不接收未解题目的完整数据。
- 每个用户/IP 对猜测、建房、入房设滑动窗口限流；搜索接口限制最小输入长度和请求频率。
- 计时使用服务器单调时间；拒绝过期、重复、错误房间状态和不在候选集内的猜测。
- 匿名用户不可进入排位型多人对战；异常高频、自动化模式和多账号关联进入风控队列，支持从榜单隐藏或作废。
- 保存事件日志（请求 ID、用户、房间、题目版本、结果），关键指标包括日活、完成率、平均猜测数、房间完成率、断线率、WebSocket 延迟及作弊拦截数。

## 7. 发布阶段与成功指标

| 阶段  | 能力                               | 通过标准                                 |
| ----- | ---------------------------------- | ---------------------------------------- |
| Alpha | 查选手、后台题库、三难度单人对战   | 50 名测试者能无人工协助完成一局          |
| Beta  | 登录、单人榜、私密多人房           | 95% 对局可正常结算，P95 事件延迟 < 300ms |
| V1    | 在线匹配、总排行榜、举报和运营工具 | D7 留存 ≥ 20%，多人房完成率 ≥ 80%        |
